# Troubleshooting

Здесь собраны ошибки, с которыми я столкнулся при настройке проекта и запуске LLM, и способы их решения.

1. Ошибка формата учетных данных (Invalid credentials format)
    Что видел: При запуске скрипта в терминале появлялась надпись `Invalid credentials format. Please use only base64 credentials` и `Оба провайдера недоступны`. Иногда выводилась ошибка `[SSL: UNEXPECTED_EOF_WHILE_READING]`.
    Почему: Ключ `GIGACHAT_CREDENTIALS` в файле `.env` был специально испорчен , из-за чего сервер Сбера не мог его декодировать. Ошибка SSL возникала из-за обрыва соединения при попытке передать неверные данные.
    Что сделал: Проверил файл `.env`, вернул нужные символы и получил оригинальный, рабочий ключ `Authorization key`.

2. Ошибка отсутствия переменной (GIGACHAT_CREDENTIALS не найден)
    Что видел: В терминале выводилось сообщение `Оба провайдера недоступны: GIGACHAT_CREDENTIALS не найден в .env`.
    Почему: При редактировании файла `.env` я случайно удалил само название переменной (слово `GIGACHAT_CREDENTIALS=`), оставив только сам ключ.
    Что сделал: Восстановил строку в формате `GIGACHAT_CREDENTIALS=ваш_ключ`.

3. Исчерпание лимитов HuggingFace (402)
    Что видел: При срабатывании резервного провайдера выводилась ошибка `Error code: 402 - {'error': 'You have no remaining credits...'}`.
    Почему: На платформе HuggingFace закончились бесплатные пробные кредиты (токены). Это внешнее ограничение сервиса, а не ошибка кода.
    Что сделал: Убедился, что механизм fallback (резервного переключения) работает корректно: скрипт не упал, а просто вывел сообщение `Переключаюсь на резервный провайдер...` и обработал ошибку. Для дальнейшей работы использовал GigaChat.

4. Ошибка синтаксиса Python (IndentationError)
    Что видел: После написания блока `try/except` терминал выдал `IndentationError: expected an indented block after 'try' statement on line 144`.
    Почему: В Python код, который находится внутри `try` и `except`, обязательно должен быть сдвинут вправо (иметь отступ). Изначально вызовы функций были прижаты к левому краю.
    Что сделал: Выделил строки внутри блоков сдвинул их на нужное количество пробелов.

5. Ошибка типа данных (TypeError)
    Что видел: Сначала `TypeError: 'ellipsis' object is not subscriptable` (когда вместо вызова функции осталось многоточие `...`), а затем `TypeError: 'function' object is not subscriptable`.
    Почему: В первом случае я оставил заглушку из методички. Во втором — забыл поставить круглые скобки при вызове функции (написал `call_gigachat` вместо `call_gigachat(question)`), из-за чего в переменную передавалась сама функция, а не её результат.
    Что сделал: Заменил многоточия на реальные вызовы функций и добавил обязательные круглые скобки с аргументом `question`.
